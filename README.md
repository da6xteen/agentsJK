# SAQ QURYLYS (САК КУРЫЛЫС) — Система мониторинга рисков в долевом жилищном строительстве

Веб-приложение для аналитиков МИО (Местных исполнительных органов) Республики Казахстан для мониторинга и выявления рисков незаконного привлечения средств дольщиков в строящихся жилых комплексах.

---

## 🏛 Юридические и этические ограничения

1. **Оценка, а не вердикт:**
   Система **НЕ** устанавливает факт правонарушения и не выносит юридический вердикт. Запрещены формулировки «объявление незаконно», «мошенничество». Допустимы только формулировки: *«обнаружены признаки риска»*, *«требуется проверка аналитиком»*.

2. **Соблюдение правил площадок и законодательства:**
   - Сбор публичной информации с портала Krisha.kz выполняется с соблюдением `robots.txt`, тайм-аутов, задержек между запросами и корректным `User-Agent`.
   - Для Telegram используется официальный механизм публичного веб-превью (`t.me/s/<channel>`) без авторизации, либо Telethon через API keys (`TELEGRAM_API_ID` / `TELEGRAM_API_HASH`).
   - Для Instagram обход защиты запрещён. Поддерживается (а) импорт по вставленной ссылке/тексту поста и скриншоту, либо (б) заглушка под официальный Graph API при наличии ключа `INSTAGRAM_GRAPH_TOKEN`.
   - Все тестовые данные являются вымышленными и помечены бейджем **«ДЕМО»**. Реальных персональных данных и реальных компаний нет.

## 🤖 ИИ-агенты

### Агент 1 — Сборщик объявлений (Raw Ad Collector)
Находит рекламные публикации о продаже квартир в строящихся ЖК на Krisha.kz, в Telegram и Instagram, а также принимает ручные публикации аналитика и сохраняет их в виде сущности `RawAd` (`Публикация`).

#### Адаптеры источников (`agents/collector/adapters/`):
1. **`KrishaAdapter`**: загружает публичную страницу по URL или запросу, парсит HTML (заголовок, описание, цена, маскированный телефон, адрес) с обработкой ошибок и таймаутами.
2. **`TelegramAdapter`**: читает публичные каналы через `https://t.me/s/<channel>` без авторизации (при наличии `TELEGRAM_API_ID` в `.env` может использоваться Telethon).
3. **`InstagramAdapter`**: работает через ручной импорт ссылки/текста и загруженного скриншота, либо через API stub при наличии токена.
4. **`ManualAdapter`**: прямая форма ручного ввода объявлений с загрузкой скриншотов.
5. **`DemoAdapter`**: читает не менее 12 вымышленных объявлений из `seed/demo_ads.json` с разной терминологией (бронь, задаток, депозит, закрепим за вами квартиру, гарантия цены взносом).

#### Общая логика сбора:
- **Дедупликация:** по SHA-256 хэшу от нормализованного текста и URL.
- **Предварительный фильтр релевантности:** проверка ключевых слов (`строящ`, `ЖК`, `сдача`, `котлован`, `долевое`, `новостройка`, `квартира`) без участия LLM. Нерелевантные публикации сохраняются со статусом `filtered` и причиной.
- **Отказоустойчивость:** ошибки сети или битый HTML не роняют конвейер, запись получает статус `error`.

### Агент 2 — Сопоставитель и Экстрактор платежей (Ad Matcher & Payment Extractor)
Выполняет автоматический анализ публикаций для извлечения платежных условий и сопоставления объявлений с объектами (ЖК) и застройщиками в локальном реестре.

#### Часть А. Экстрактор платежных условий
Извлекает информацию о требованиях взносов, брони, депозитов до проверки правовых оснований.

##### Валидируемая JSON-схема ответа (`PaymentExtractorResult`):
```json
{
  "offers_payment": true,
  "payment_type": "бронь|депозит|задаток|первоначальный_взнос|иное|нет",
  "amount": 500000.0,
  "currency": "KZT|USD|null",
  "evidence_quote": "дословный фрагмент из текста",
  "confidence": 0.85,
  "reasoning_short": "1 краткое предложение",
  "source": "llm|rules"
}
```

##### Ключевые механизмы:
- **LLM Провайдер:** поддержка Anthropic Claude API (через `ANTHROPIC_API_KEY`) с передачей мультимодальных данных (текст + скриншот для vision).
- **Валидация цитат (Постпроверка):** `evidence_quote` обязана буквально (после нормализации пробелов и регистра) встречаться в исходном тексте объявления. При отсутствии цитаты гипотеза отбрасывается.
- **Ключевой Fallback режим (Offline/Keyless):** при отсутствии API ключа или сбое LLM выполняется детерминированный regex-анализ по корням (`брон`, `депозит`, `задаток`, `взнос`, `предоплат`, `закреп`, `аванс`) с извлечением сумм и валют. Помечает источник вывода как `"rules"`.
- **Порог уверенности:** если `confidence < 0.6`, система выставляет статус *"Нужна проверка"*.

---

#### Часть Б. Сопоставитель с ЖК и застройщиком (Agentic Tool-Use Loop)
Выполняет сопоставление публикации с реестром строящихся жилых комплексов и застройщиков через агентный цикл вызова инструментов (tool use) до 5 шагов.

##### Инструменты агента (`agents/matcher/tools.py`):
1. `find_residential_complex(query)`: нечёткий поиск ЖК по названию, адресу, району, городу или застройщику.
2. `get_developer(bin_or_name)`: карточка застройщика по БИН или наименованию.
3. `list_ads_by_phone(phone_hash_or_account)`: поиск других объявлений с тем же контактом (телефоны хранятся только в виде хэша/маскированно).
4. `get_complex(id)`: полная карточка ЖК.

##### Правила и пороги авто-привязки:
- **Авто-привязка (`linked`):** выполняется **ТОЛЬКО** если уверенность топового кандидата `confidence >= 0.75` (настраивается в конфиге) **И** отрыв от второго кандидата `(top1_confidence - top2_confidence) >= 0.15`.
- **Ручная проверка (`Нужна проверка`):** если пороги не достигнуты, автоматическая привязка `complex_id` **НЕ** производится, а список кандидатов выводится аналитику для ручного выбора в UI.
- **Fallback режим:** детерминированное нечёткое сопоставление на базе `rapidfuzz` (нормализация, токены, совпадения названий, адресов, районов и застройщиков).

### Агент 3 — Объяснитель риска (Risk Explainer Agent)
Формирует для аналитика МИО объяснение, ПОЧЕМУ конкретная публикация и жилой комплекс требуют проверки, не вынося при этом юридических вердиктов и заявляя о правонарушениях.

#### Входные данные (собираются строго кодом, без участия LLM):
- Карточка ЖК и застройщика.
- Результат работы детерминированной функции `check_legal_basis(complex_id)`.
- Список подтверждённых факторов с баллами и привязанными доказательствами (`evidence_ids`).
- Список вопросов, требующих проверки аналитиком (`needs_verification`).
- Рассчитанный итоговый балл риска и зона риска.

#### Задача LLM и валидируемая JSON-схема (`RiskExplanationOutput`):
```json
{
  "summary": "Текст объяснения на русском языке (3–6 предложений)",
  "factor_explanations": [
    {
      "code": "R2",
      "points": 25,
      "text": "Пояснение фактора",
      "evidence_ids": ["hyp-123"]
    }
  ],
  "needs_verification": ["Что именно и где проверить"],
  "disclaimer": "Оценка риска — не юридическое заключение."
}
```

#### Жесткие ограничения и механизмы защиты:
1. **Запрет юридических вердиктов:** Формулировки «незаконно», «мошенничество», «нарушил закон», «виновен» строго запрещены. Проверяется автоматическим постфильтром кодом. При обнаружении — 1 повтор с коридором ошибки, далее переключение на fallback.
2. **Валидация ссылок на доказательства:** Все `evidence_ids` в выгрузке проверяются кодом на соответствие переданным. Несуществующие ID бракуются.
3. **Объяснение статуса правового основания (R1):** Объясняет, какие разрешения учтены, и почему R1 начислен или не начислен (в т.ч. указывая, что «основание не проверено — это не нарушение»).
4. **Keyless / Offline Fallback:** При отсутствии API-ключей или отказе LLM формирует структурированное объяснение из шаблонов без потери функциональности.
5. **Логирование:** Все обращения фиксируются в таблице `llm_logs` (агент `explainer`, модель, промпт, ответ, время, результат валидации).

## 🏛 Реестр разрешений и проверка правовых оснований (`data/permits.json`)

В проекте реализована детерминированная система проверки правовых оснований для привлечения средств дольщиков согласно Закону РК «О долевом участии в жилищном строительстве».

### Типы правовых оснований (`permit_types`):
1. `single_operator_guarantee`: Гарантия Единого оператора (АО «КЖК»).
2. `mio_permit`: Разрешение местного исполнительного органа (МИО).
3. `bank_project_financing`: Участие в проекте банка второго уровня (проектное финансирование БВУ).

### Функция `check_legal_basis(complex_id, as_of_date)`:
Возвращает один из трёх строго детерминированных статусов:
- **`CONFIRMED_VALID`**: Есть действующее подтверждённое разрешение/основание подходящего типа (с источником и датой проверки) $\rightarrow$ **R1 НЕ начисляется (+0 б.)**. Отсутствие разрешения МИО не рождает риск, если есть гарантия КЖК.
- **`ABSENCE_ESTABLISHED`**: Проверенными данными официально установлено отсутствие Любого применимого основания (запись проверки с источником, датой и результатом `absence_established`) $\rightarrow$ **начисляется фактор R1 (+35 б.)**.
- **`UNVERIFIED`**: Данных нет, реестр недоступен, просроченное/отозванное разрешение без подтверждённого акта отсутствия $\rightarrow$ **R1 = 0 б.**, выставляется пометка *«Нужна проверка»*.

## 💡 Использование ИИ и Детерминированный Скоринг

- **Гипотеза ИИ:** любой вывод ИИ в рамках системы — это **ГИПОТЕЗА** (статус `pending`) с обязательной цитатой-основанием и показателем уверенности (0..1).
- **Подтверждение человеком:** гипотеза становится подтверждённым фактором риска **ТОЛЬКО** после того, как аналитик нажал кнопку **«Принять»**.
- **Строгий детерминированный скоринг (`agents/scoring.py`):** LLM никогда не считает балл риска и не определяет итоговую зону риска. Балл считает исключительно детерминированный код:
  $$\text{Score} = \min(100, \sum \text{веса подтверждённых факторов})$$

##### Веса факторов:
- `R1`: **+35** (установлено отсутствие применимого правового основания)
- `R2`: **+25** (прямое предложение внести деньги: бронь, депозит, взнос)
- `R3`: **+10** (реклама строящегося жилья / долевого строительства)
- `R4`: **+15**, `R5`: **+10**, `R6`: **+5**

##### Зоны риска:
- 🟢 **Зелёная зона (0–24):** Низкий риск.
- 🟡 **Жёлтая зона (25–59):** Средний риск (требуется проверка аналитиком). Также 60+ без одновременно подтверждённой пары R1+R2.
- 🔴 **Красная зона (60+):** Высокий риск (обнаружены признаки риска) — устанавливается при балле >= 60 **И** одновременно подтверждённых факторах R1 и R2.

##### Валидация ответов LLM:
Форматирование строго в JSON с валидацией Pydantic. При невалидном ответе производится 1 повтор с уточнением промпта, после чего включается fallback. В лог `llm_logs` фиксируются: агент, модель, промпт, ответ, время, исход валидации.

## 🚀 Запуск без ключей и без интернета (Keyless / Offline Mode)

Приложение полностью автономно и работает без внешних ключей API и без интернета:

```bash
# 1. Установка зависимостей
pip install -r requirements.txt

# 2. Запуск FastAPI сервера
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Веб-интерфейс доступен по адресу: `http://localhost:8000`

### Переменные окружения (.env)
Скопируйте `.env.example` в `.env` при необходимости добавить ключи:
- `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`
- `OPENAI_API_KEY`, `LLM_MODEL`
- `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`
- `INSTAGRAM_GRAPH_TOKEN`

## 🤖 Раздел «Использование ИИ»

### 1. Где ИИ используется в продукте:
- **Агент 2 (Часть А - Экстрактор платежных условий):** извлекает условия бронирования, депозитов и взносов из неструктурированного текста и изображений публикаций.
- **Агент 2 (Часть Б - Сопоставитель ЖК):** через агентный цикл вызова инструментов (tool-use loop) выполняет поиск и нечёткое сопоставление объявлений с реестром застройщиков и ЖК.
- **Агент 3 (Объяснитель риска):** генерирует краткие структурированные резюме на русском языке для аналитиков МИО с объяснением обнаруженных факторов риска.
*Важно: LLM никогда не принимает решений, не рассчитывает баллы и не определяет зоны риска. Все выводы ИИ имеют статус «Гипотеза ИИ» и требуют явного принятия аналитиком МИО.*

### 2. Какие ИИ-инструменты использовались при разработке:
- **Claude / Anthropic API (Claude 3.5 Sonnet):** для работы нейросетевых агентов внутри приложения.
- **Jules / AI Coding Assistant:** для проектирования архитектуры, написания кода, валидации Pydantic-схем, создания автотестов и документации.

### 3. Что проверено вручную:
- Корректность работы детерминированного математического алгоритма расчёта баллов risk score и распределения по зонам (Зелёная, Жёлтая, Красная).
- Формула проверки правовых оснований `check_legal_basis` (Кейсы A, B, C, просроченные разрешения, отсутствие данных).
- Работа постфильтра запрещённых формулировок («незаконно», «мошенничество») и авто-переключение на fallback при отсутствии ключей API.
- Прохождение полного пакета из 27 юнит- и интеграционных автотестов.
